# NAPAR 0.2 — Minecraft-компаньон

Отдельный серверный игрок Napar в Minecraft Java 26.2. Java 25 + Fabric + Carpet
исполняют обычные игровые действия; Python + GPT через совместимый API выбирают
цели и тактику, общаются по-русски и ведут долговременную память.

## Возможности

- Видимый отдельный игрок; сообщения хозяина через «Напар, …» и /napar ask.
- Наблюдение за здоровьем, едой, воздухом, эффектами, бронёй, прочностью предметов,
  погодой и видимыми существами. Активный осмотр видимых блоков, инвентаря,
  рецептов и открытых контейнеров; скрытые руды не раскрываются.
- Локальные маршруты по поверхностям блоков, плитам и лестницам, прыжок на блок,
  спуск до двух блоков, плавание по поверхности. Постоянное следование до остановки.
- Настоящая добыча с временем разрушения и износом; размещение блоков из инвентаря;
  еда, экипировка, подбор и выбрасывание предметов.
- Ближний бой с обычным временем восстановления удара; тактика со щитом.
- Крафт по зарегистрированным рецептам с расходом материалов и возвратными предметами;
  большой рецепт требует доступного верстака. При невозможности полного пакета
  инвентарь сохраняется.
- Открытие контейнеров, перенос точного количества через правила слотов; загрузка
  печи и последующее получение реально переплавленного результата; сон.
- SQLite: история разговора, цели с подцелями и приоритетами, проверяемый успех,
  память по мирам с уверенностью/источником, история исправленных воспоминаний,
  наблюдения местности и извлечённые из подтверждённых действий уроки.
- Открытый веб-поиск и чтение публичных текстовых страниц с URL/датой получения,
  приоритетом Minecraft-источников. Внешние тексты считаются недоверенными.
- Короткий план до восьми игровых действий выполняется без нового запроса GPT
  на каждый шаг; любая ошибка или остановка прерывает остаток.
- Локальные рефлексы еды, всплытия и попытки ухода от лавы/взрывающегося крипера.
  Стратегию после события пересматривает модель.
- Возрождение в точке, вычисленной Minecraft; восстановление отдельного игрока
  после перезапуска сервера без подключения человека.

## Ограничения

Это игровой компаньон с ограниченными контроллерами, а не гарантированное прохождение
любой задачи. Одна навигация охватывает до 32 блоков в загруженных чанках и до
4096 узлов поиска. Модель может выбирать следующие точки. Сложный паркур, пролёты
над пропастью, полёт, езда и дальний бой не реализованы. Baritone не подключён:
его клиентский контроллер нельзя автоматически считать совместимым с серверным
Carpet FakePlayer; здесь используется собственный серверный A*.

Крафт охватывает размещаемые рецепты CraftingRecipe; специальные динамические
рецепты без placementInfo требуют отдельного контроллера и честно отклоняются.
Загрузка печи подтверждает только загрузку, готовность проверяется отдельно.
Бой не обеспечивает неуязвимости; рефлексы не гарантируют спасения в любой опасности.
Веб-поиск зависит от доступности публичного поискового сервиса и сайтов.

## Устройство и защита

Сервис мозга слушает только 127.0.0.1:8000. Все управляющие HTTP-запросы требуют
случайного Bearer Token. Только настроенный хозяин может поручать задачи в чате.
Сессии, возрастающая последовательность, TTL действий, идемпотентные результаты,
подтверждение снимка после действия и поколение остановки защищают от старых команд.
Потеря связи более трёх секунд останавливает управление.

Ключи находятся только в .env, не в репозитории. GPT не получает доступ к shell
или к файлам VPS. Веб-чтение ограничивает объём и время; каждый переход проверяет
публичный DNS и закрепляет IP соединения, запрещая доступ к localhost/частным сетям.

## Запуск

Python >=3.12. Установить проект через pip install -e ".[test]", скопировать
.env.example в .env, задать случайный NAPAR_BRIDGE_TOKEN, хозяина и параметры модели.
Запуск: napar. Проверка: pytest -q.

Для Minecraft: minecraft-mod/bootstrap.ps1 получает закреплённую зависимость Carpet;
gradlew build собирает мод. Версии: Minecraft 26.2, Java 25, Loader 0.19.5,
Fabric API 0.161.0+26.2, Carpet 26.2+v260616. В процесс игры передаются
NAPAR_BRIDGE_TOKEN, NAPAR_OWNER_NAME и NAPAR_WORLD_ID.
Для изолированного стенда доступен NAPAR_BRIDGE_URL (по умолчанию localhost:8000);
NAPAR_RESTORE_PLAYER=false отключает восстановление присутствия только на стенде.

## Бюджет и самостоятельность

NAPAR_MAX_CALLS_PER_DAY — общий лимит обращений, а не денежная сумма; 0 отключает его.
NAPAR_MAX_STEPS=0 снимает лимит шагов рассуждения за цикл. Учёт расходов сохраняется.
Вычисления модели событийные. Бесплатный локальный таймер продолжает активные цели
только при NAPAR_INITIATIVE_SECONDS > 0; фоновым циклам недоступна последняя половина
дневного лимита, если он включён. Постоянное следование и рефлексы не вызывают GPT каждый тик.

Режимы через просьбу хозяина: «жди команд», «обычная самостоятельность»,
«расширенная самостоятельность». В normal продолжаются порученные цели; в expanded
можно безопасно исследовать рядом. «Стоп» приостанавливает цели и действия, они
не возобновляются сами как после технического перезапуска.

## Проверка и обновление существующего VPS

Автотесты покрывают протокол, отмену, бюджет, цели, миграции и область памяти,
сериализацию событий, схему tools, безопасность веб-доступа и выполнение планов.
Игровые проверки отдельно проверяют реальное расходование ресурсов, добычу,
контейнеры, печь, движение, еду, бой, подбор, следование, смерть и перезапуск,
а также плиты, лестницы, воду, щит и сон. Это отдельный тестовый мир без платного API.
Повторяемый стенд: integration/game_smoke.py; дополнительный набор включается
через NAPAR_SMOKE_EXTRA=1; регрессии крафта, воды и экстренного отступления —
NAPAR_SMOKE_CRAFT=1. Перед запуском задать JAVA_HOME для JDK 25, установить
проект с test-зависимостями и принять EULA для локального тестового сервера.
Стенд использует localhost:8001/25575 и отдельный world-acceptance; результаты
сохраняются в test-artifacts (путь можно задать через NAPAR_SMOKE_OUTPUT).

deploy/upgrade_companion.py проверяет подготовленную версию до остановки служб,
сохраняет предыдущий код, настройки и SQLite, устанавливает проверенный по SHA-256
мод, восстанавливает присутствие по сохранению Minecraft и проверяет обе службы.
При неудаче возвращает прежнюю сборку; рядом остаётся самостоятельный rollback.py.
Исходный старый мир в /opt/minecraft не изменяется.

brain.py — только совместимый запуск основной реализации src/napar; второго мозга нет.


## Исправления 19 октября 2026

Простые «иди за мной», «стоп», «останься на сервере» и «выходи после меня»
обрабатываются локально без вызовов модели. Следование сохраняется при временной
потере видимости и сбое маршрута; используются последние видимые точки и повторный
поиск пути. При отставании бот может бежать, если хватает еды.

При отсутствии владельца и активной работы Напар выходит через 120 секунд.
Просьба остаться сохраняется отдельно для каждого мира. Состояние выхода
сохраняется при перезапуске, владелец своим входом возвращает Напара в игру.
NAPAR_IDLE_LOGOUT_SECONDS задаёт интервал для игрового процесса (по умолчанию 120).

Обновление deploy/upgrade_companion.py по умолчанию выключает платную модель:
NAPAR_PAID_ENABLED=false, NAPAR_LLM_BACKEND=disabled, NAPAR_INITIATIVE_SECONDS=0.
Игровой мост остаётся включён для бесплатных команд. Ошибки API 401/402/403
теперь защёлкивают запрет повторов в SQLite до ручного разблокирования;
повторение одинаковых инструментов без прогресса останавливает текущий цикл.
Обновление не включает оплату обратно. Манера общения модели изменена в SYSTEM.
Актуальное состояние конкретной установки нужно проверять на самом VPS.

Для выбранного владельцем Gemini 3.8 Flash Free через BeatAPI предусмотрен
deploy/switch_beatapi.py. Он проверяет модель с полным набором схем инструментов,
сохраняет предыдущие настройки и меняет только мозг, без перезапуска Minecraft.
При HTTP 429 проверка повторяется один раз с паузой; при повторном отказе
бесплатный маршрут сохраняется с явным model_verified=false. Подмена платной
моделью не выполняется. Другие ошибки доступа сохраняют прежнюю конфигурацию.

NAPAR_LLM_MIN_INTERVAL_SECONDS=61 выдерживает бесплатное окно между запросами,
включая начало работы после перезапуска. Это может замедлять разговор и сложные
поручения; локальные команды следования и остановки продолжают работать сразу.
Фоновые обращения при NAPAR_INITIATIVE_SECONDS=0 не выполняются.

Стенды: NAPAR_SMOKE_FOLLOW=1 — движущийся игрок, потеря видимости и стоп;
NAPAR_SMOKE_PRESENCE=1 — выход без работы, просьба остаться, незавершённая
задача, перезапуск и возвращение владельца. Оба режима выполняются без модели.

# Napar — мозг Minecraft-напарника

Проект разделяет «мозг» и игровое тело. Мозг хранит опыт и цели в SQLite, принимает
ограниченные события, решает через инструменты и ждёт подтверждения от игрового
адаптера. Адаптер Fabric в игру пока не входит: его контракт уже зафиксирован в
`src/napar/protocol.py`, поэтому его можно заменить без переписывания памяти и
планировщика.

## Что работает сейчас

- память с областью `world_id`, источником и временем обновления;
- цели, которые после перезапуска становятся `paused` и требуют новой проверки;
- одно подключение игрового тела с последовательностью snapshot и защитой от старой сессии;
- очередь действий с TTL, дедупликацией результата и остановкой при устаревшем состоянии;
- инструменты `observe`, `recall`, `remember`, `create_goal`, `update_goal` и удалённые
  `inspect`, `move_to`, `follow_player`, `look_at`, `stop`, `say`;
- дневной лимит вызовов модели и журнал действий;
- защищённый HTTP API и `/v1/stop`;
- режим `disabled`, который не делает сетевых вызовов, и совместимый OpenAI backend.

## Локальный запуск

```powershell
py -3.14 -m venv .venv
& .\.venv\Scripts\Activate.ps1
pip install -e ".[test]"
Copy-Item .env.example .env
python -c "import secrets; print(secrets.token_urlsafe(32))"
# вставить случайную строку в NAPAR_BRIDGE_TOKEN в .env
pytest -q
napar
```

Сервис слушает только `127.0.0.1:8000`. Проверка без авторизации: `GET /health`.
Остальные endpoints требуют `Authorization: Bearer <NAPAR_BRIDGE_TOKEN>`.

Для подключения модели задать `NAPAR_LLM_BACKEND=openai`, ключ и совместимый
`NAPAR_LLM_BASE_URL`. Текущий backend использует Chat Completions tool calls,
модель по умолчанию — `gpt-4o-mini`; тесты всегда работают с отключённой моделью.

## Установка рядом с Minecraft на VPS

На сервере уже запущен Fabric на `25565`. Мозг должен жить отдельным пользователем
и процессом, слушая localhost; игровой адаптер будет единственным клиентом API.

```bash
install -d -m 0750 /opt/napar/data
useradd --system --home /opt/napar --shell /usr/sbin/nologin napar 2>/dev/null || true
chown -R napar:napar /opt/napar
```

Скопировать проект в `/opt/napar`, создать `/opt/napar/.env` с токеном минимум 32
символа и запустить подготовленный unit:

```bash
cp deploy/napar.service /etc/systemd/system/napar.service
systemctl daemon-reload
systemctl enable --now napar
curl http://127.0.0.1:8000/health
```

Публиковать порт `8000` в интернет не нужно. Перед установкой на реальный сервер
сначала сделать резервную копию `.env` и папки данных. Команды установки и unit
не трогают каталог Minecraft и не перезапускают его.

## Следующий этап

Нужен Fabric-адаптер для версии сервера: он будет отправлять snapshot и события,
получать действия, выполнять их локально с аварийным `stop` и возвращать результат.
Сначала подключаются наблюдение, чат и короткие перемещения; бой и дальняя
навигация добавляются после проверки нагрузки. Без второго Java-аккаунта возможен
серверный fake-player через совместимый серверный мод, но это отдельный вариант
тела и не подменяет контракт мозга.
